# Как пользоваться и готовить демонстрацию

## 1. Сейчас на компьютере

Открыть http://localhost:3000. Админка: http://localhost:3000/admin.

Логин `owner`, первоначальный локальный пароль `kruti-local-2026`. Это пароль демонстрации; не использовать на внешнем сервере. Новый пароль в ADMIN_PASSWORD задаётся до первого запуска новой базы. Для существующего владельца используется `scripts/reset-owner.mjs` и переменная окружения NEW_OWNER_PASSWORD; пароль не передаётся аргументом команды и не выводится в лог.

Если приложение остановлено:

```sh
npm ci
npm start
```

Компьютер с закрытым приложением или в режиме сна не обслуживает заказы. Это локальная демонстрация.

## 2. Что показать владельцу

1. Выбрать блюдо, добавить сыр, изменить количество.
2. Открыть корзину и подтвердить демооплату. Деньги не списываются.
3. В отдельном окне открыть админку: «Начать готовить» → «Готово к выдаче».
4. Ввести код с клиентского экрана. Повторно выдать заказ нельзя.
5. В истории сделать полный демовозврат.
6. В «Настройках точки» поменять расписание. В «Меню» изменить цену или добавить блюдо.
7. Создать повара. У повара нет доступа к возвратам, настройкам и сотрудникам.
8. Открыть «Состояние системы», показать копию БД и журнал действий.

Не выдавать демонстрационные цены/картинки и часы за реальные данные заведения.

## 3. Где взять тестовую ЮKassa

Официальная инструкция: https://yookassa.ru/docs/support/merchant/payments/implement/test-store

В кабинете ЮKassa открыть список сервисов → добавить магазин → выбрать тестовый. Переключиться в тестовый магазин. Открыть «Интеграция → Ключи API» и выпустить секретный ключ. Найти shopId выбранного тестового магазина.

В локальном `.env` заполнить:

```dotenv
PAYMENT_MODE=yookassa_test
YOOKASSA_SHOP_ID=идентификатор_тестового_магазина
YOOKASSA_SECRET_KEY=тестовый_секретный_ключ
```

Остальные параметры локального запуска оставить. Перезапустить `npm start`. Для возврата к демонстрации без API установить `PAYMENT_MODE=demo` и перезапустить.

`.env` уже исключён из Git. Не публиковать его, не вставлять ключ в клиентский JavaScript, чат или скриншот. Если ключ утёк, отозвать его в ЮKassa и выпустить новый.

Тестовые карты брать из [официального раздела тестирования](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing). Использовать тестовые реквизиты. Тестовый режим проверяется сервером по ответу провайдера.

Публичная ЮKassa не может доставить webhook на localhost. Локальная фоновая сверка делает исходящие запросы к API; для проверки входящих уведомлений нужен staging HTTPS. Настроить адрес `https://ВАШ-ДОМЕН/api/payments/webhook` для payment.succeeded и payment.canceled. Возвраты приложение также сверяет фоновыми запросами.

## 4. Как устроен код

| Файл | Ответственность |
|---|---|
| `public/index.html`, `style.css`, `night.css` | Структура и оформление |
| `public/app.js` | Корзина, оформление, статусы и админка |
| `server/domain.mjs` | Каталог по умолчанию, расчёт цены, подпись Telegram |
| `server/index.mjs` | HTTP, сессии, права, маршруты, настройки |
| `server/payments.mjs` | Долговременные платёжные операции, сверка и возвраты |
| `server/platform.mjs` | Таблицы, сотрудники, настройки и расписание |
| `server/operations.mjs` | Копии и запрет второго процесса на одной базе |
| `data/kruti.sqlite` | Заказы, сессии, сотрудники, очередь и настройки |

Покупатель передаёт выбранные позиции. Сервер считает цену и сохраняет снимок заказа. До обращения к ЮKassa сервер сохраняет запрос и ключ операции. Подтверждённый провайдером платёж переводит заказ на кухню; поздняя оплата требует решения управляющего. Код выдачи проверяет сервер. Слова покупателя «я оплатил» не меняют статус.

## 5. Резервные копии

```sh
npm run backup
node scripts/restore.mjs ПУТЬ-К-КОПИИ.sqlite НОВАЯ-ПАПКА
```

Рядом с копией нужен файл `.sha256`. Восстановление не перезаписывает существующую папку, проверяет целостность и отзывает сессии. После восстановления запустить приложение с DATA_DIR новой папки, закрыть приём заказов, сверить неопределённые платежи с ЮKassa и только затем возобновить работу. Хранить внешнюю копию отдельно от диска приложения.

## 6. Подключение следующего клиента

Одна установка на клиента, без копирования случайных правок ядра. Владелец регистрирует бота, хостинг, домен, ЮKassa и кассу на свои данные. Ты получаешь ограниченный доступ для настройки. Деньги за еду идут на его магазин; твоя плата за разработку/поддержку оформляется отдельно.

Использовать тот же релиз, отдельную БД, секреты и настройки точки. Пример конфигурации — `config/vkus-vostoka.demo.json`. Применение к запущенной локальной установке: `node scripts/configure-store.mjs config/vkus-vostoka.demo.json`.

Для сервера подготовлены Docker Compose + Caddy и прежний Render blueprint. Перед применением — решение о размещении данных, DNS, HTTPS, ключи, доступы, копии, мониторинг и испытания. См. `RELEASE.md`: готовность конфигурационных файлов не равна готовности сервера.
