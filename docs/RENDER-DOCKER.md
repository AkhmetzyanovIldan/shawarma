# Render: Docker и постоянный диск

Если лог сборки содержит `load build definition from Dockerfile`, выбран Docker runtime. Команды Build/Start из Node blueprint к нему не применяются.

1. В Environment установить `DATA_DIR=/var/data`.
2. В Disks подключить persistent disk с Mount Path `/var/data`. Создание папки в образе не создаёт постоянный диск. На бесплатном сервисе такой диск недоступен.
3. Поле Docker Command оставить пустым: используется CMD из Dockerfile. Не переопределять его на `npm start` или `node server/index.mjs`, поскольку они пропустят подготовку смонтированного диска.
4. Выполнить Manual Deploy → Deploy latest commit.

Контейнер сначала подготавливает права самой папки данных, затем сбрасывает дополнительные группы и переключается на UID/GID 1000 (`node`). Только после этого загружается HTTP-сервер. Содержимое диска рекурсивно не меняется, база не удаляется. Поддерживаются `/var/data` для Render и `/app/data` для существующего Compose.

Ошибка `EACCES: mkdir '/var/data'` в старом образе возникала потому, что для пользователя node была подготовлена только `/app/data`. Исправление образа не заменяет подключение диска: без него новые данные будут временными.

Проверка после запуска: `/api/health` возвращает `{"ok":true}`, настройки точки сохраняются после перезапуска. Для проверки сохранности использовать тестовую настройку, не удалять и не заменять имеющийся диск.

Документация: [Render Disks](https://render.com/docs/disks), [Docker on Render](https://render.com/docs/docker).
