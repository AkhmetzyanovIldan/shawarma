# Fast-food Mini App · «Вкус востока»

Локальная демонстрация заказов для точки «Вкус востока», Москва, ул. Академика Волгина, 1. Меню, цены, фотографии и часы демонстрационные.

**Обновлено 22.09.2026:** редактор каталога, расписание, роли сотрудников, журнал действий, долговременные платёжные операции, сверка, полный возврат, резервные копии и восстановление. Реальная ЮKassa и промышленная инфраструктура ещё не подключены.

## Запуск

Нужен **Node.js 24.x**. У приложения нет внешних runtime-зависимостей.

```sh
npm ci
npm start
```

- Витрина: http://localhost:3000
- Админка: http://localhost:3000/admin
- Локальный логин: `owner`, первоначальный пароль: `kruti-local-2026`. ADMIN_PASSWORD используется только при создании первой учётной записи; восстановление пароля существующего владельца — `scripts/reset-owner.mjs`.
- Проверки: `npm test` и `npm run build`
- Браузерный сценарий: `npm run test:browser` (Windows: установленный Edge; Linux/macOS: сначала `npx playwright install chromium`). Он запускает отдельный сервер на 3002 и временную базу, не изменяя ваши заказы.
- Разработка с перезапуском сервера: `npm run dev`

Для своих параметров скопируйте `.env.example` в `.env`. Ключи не должны попадать в Git. Локальный сервер слушает только `127.0.0.1`.

## Что работает

- Шесть блюд, категории, обычный/XL размер шаурмы, шесть платных добавок.
- Корзина с сохранением на устройстве; цену заказа рассчитывает сервер.
- Самовывоз сразу, через 15 или 30 минут, комментарий к заказу.
- Демо-оплата без карты и без списаний.
- Серверный адаптер ЮKassa с redirect-оплатой, повторяемыми запросами создания платежа и проверкой статуса через API.
- Заказы и сессии хранятся в SQLite, переживают перезапуск.
- Админка: пароль, HttpOnly cookie, очередь, история, стоп-лист и приостановка заказов.
- Статусы: принят → готовим → готов → выдан. Код доступен покупателю после оплаты; администратору полный код не передаётся. Администратор вводит его с экрана покупателя, сервер проверяет и погашает код.
- Telegram SDK: разворачивание, цвета, тактильный отклик. Сервер проверяет подпись `initData` и её возраст; для размещённой версии заказы доступны только после входа через Telegram.

Это подтверждение владения кодом заказа, а не паспортной личности. Переданный другому человеку код позволит забрать заказ. После выдачи повторное использование исключено. Покупателю не следует делиться экраном с кодом.

## Render — подготовлено, ещё не опубликовано

Обновление от 18.09.2026: следующие шаги — техническая конфигурация прототипа, **не утверждённая схема размещения реальных данных покупателей РФ**. У Render нет российского региона. Для коммерческого запуска требуется пересмотреть географию обработки и хранения, включая логи/копии, а также выполнить аудит платежей и фискализации из [плана развития](docs/product/03-audit-and-roadmap.md). Демонстрацию на синтетических данных можно оставить на Render.

`render.yaml` описывает один Node Web Service, который отдаёт и фронтенд, и API. Так не нужны отдельный CORS и cookies между доменами. База лежит на постоянном диске `/var/data`.

1. Создайте GitHub-репозиторий и отправьте сюда исходники.
2. В Render создайте Blueprint из репозитория. В конфигурации используется **платный Starter и persistent disk**. Создание инфраструктуры пока не выполнялось.
3. Укажите переменные: `APP_URL` (точный HTTPS-адрес сервиса без завершающего `/`), уникальный `ADMIN_PASSWORD` длиной от 16 символов, `TELEGRAM_BOT_TOKEN`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` тестового магазина.
4. Оставьте `PAYMENT_MODE=yookassa_test` до проверки оплаты. Режим `demo` намеренно запрещён при `NODE_ENV=production`.
5. В BotFather настройте Main Mini App / Menu Button на HTTPS URL сервиса.
6. В тестовом магазине ЮKassa добавьте webhook `https://ВАШ-СЕРВИС.onrender.com/api/payments/webhook`, события `payment.succeeded` и `payment.canceled`.
7. Пройдите тестовый платёж из Telegram, проверьте заказ и выдачу в `/admin`.

Render по умолчанию использует временную файловую систему; SQLite обязательно требует persistent disk. Этот вариант рассчитан на **один экземпляр сервера**. Для нескольких экземпляров потребуется общая база, например PostgreSQL. Настройте резервные копии данных перед эксплуатацией.

## ЮKassa: границы готовности

Сейчас запускается локальный симулятор платежа. Реальная ЮKassa **не подключена и не проверена с магазином**: реквизиты магазина и ключи не предоставлялись. Адаптер готов к интеграционному тесту. Возврат по `return_url` и нажатие «Я оплатил» сами по себе не подтверждают оплату. Сервер повторно запрашивает платёж у ЮKassa и сверяет ID, сумму, валюту, `paid`, `status`, metadata заказа и признак тестового платежа.

Для боевых платежей:

- Установите `PAYMENT_MODE=yookassa_live`, боевые ключи.
- Уточните и заполните `RECEIPT_VAT_CODE`, `RECEIPT_TAX_SYSTEM_CODE` в соответствии с настройками бизнеса и кассы. Затем установите `RECEIPTS_CONFIGURED=true`. Эти значения не подобраны автоматически.
- Включится email для чека; позиции и добавки входят в рассчитанную цену позиции чека.
- Проверьте фискализацию с вашим магазином, реальные контакты, адрес, график, документы и обработку персональных данных до запуска продаж.
- Полный возврат доступен владельцу и управляющему в админке. Частичный внешний возврат переводит заказ на проверку. Полный цикл кассовых документов ещё требует реализации под выбранную кассу; текущая настройка первоначального чека не закрывает зачёт предоплаты.

Сначала завершить [условия выпуска](docs/RELEASE.md). `LIVE_LAUNCH_APPROVED=false` блокирует случайное включение боевых платежей; не менять его до приёмки. Подготовленные Docker Compose/Caddy и Render blueprint не были развёрнуты на целевом сервере.

В Telegram реальная проверка `initData`, открытие оплаты и возврат должны быть проверены на устройстве после HTTPS-размещения. В локальном браузере используется гостевая сессия. Никакие токены или реквизиты карты не хранятся во фронтенде.

## GitHub

Репозиторий инициализирован на ветке `main`, первый коммит создан. Автор: AkhmetzyanovIldan. `origin` указывает на [AkhmetzyanovIldan/shawarma](https://github.com/AkhmetzyanovIldan/shawarma). `.env`, база, сессии, логи, снимки проверок исключены из Git. Для следующих изменений:

```sh
git add .
git commit -m "Update Kruti Mini App"
git push -u origin main
```

На этом Windows-компьютере папку `.git` создала изолированная учётная запись Codex. Смена владельца была отклонена автоматической проверкой; права доступа не менялись. Коммит можно выполнять с `git -c safe.directory=ПОЛНЫЙ_ПУТЬ_К_ПРОЕКТУ ...`, доверяя только этой известной папке. Если обычный Git у вашей учётной записи сообщает `dubious ownership`, подтвердите доверие именно к этому репозиторию в настройках Git. Не используйте доверие ко всем папкам `safe.directory=*`.

## Структура

- `public/` — готовый фронтенд без сборщика; изображения и шрифты локальные.
- `server/index.mjs` — HTTP, SQLite, авторизация, заказы, админка и ЮKassa.
- `server/domain.mjs` — каталог, расчёт цен, проверка Telegram и платежей.
- `tests/` — расчёт стоимости, подпись Telegram и полный локальный цикл заказа.
- `docs/PROMPTING.md` — исследованные рекомендации для GPT-6 Astra и готовый промпт.
- `docs/ASSETS.md` — происхождение изображений и шрифта.

`npm run build` здесь проверяет синтаксис: статические файлы уже готовы к выдаче. WebMCP предусмотрен как необязательный интерфейс открытия настройки блюда; браузер без поддержки работает как обычно. Проверка его регистрации в поддерживающем WebMCP браузере не проводилась.
